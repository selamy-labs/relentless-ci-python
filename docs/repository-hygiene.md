# Repository hygiene

The full local command and Linux analysis jobs run `python -m quality.repository_hygiene_main` from the protected check registry. The gate
compares the native Git index with the filesystem, including untracked and
ignored authored files. It rejects case or Unicode path collisions, authored
symlinks, unsupported file kinds or text types, invalid UTF-8, NUL bytes and
unresolved Git conflict-marker lines. A missing indexed file also fails.

Only declared top-level generated directories and the untracked `.coverage`
file are omitted from disk scanning. Nested Python `__pycache__` directories
are omitted as generated bytecode; the existing tracked-source gate rejects
committed bytecode caches. If a project needs another authored file type,
enroll it in `TEXT_SUFFIXES` or `TEXT_NAMES` with the corresponding clean and
defect tests through a reviewed policy change. Do not hide it in a generated
directory or use an ignore rule to evade this gate.

Resolve merge markers in the actual affected file, remove unsupported
artifacts, or rename colliding paths. The scanner treats a line beginning
with seven or more `<`, `=`, `>` or `|` characters followed by whitespace or
the line end as a conflict marker. This intentionally fails closed for
ambiguous authored text, including documentation fixtures; encode such
examples within a line or generate them in tests.
